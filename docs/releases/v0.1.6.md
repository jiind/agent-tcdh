# AgentTCDH v0.1.6

This release bundles six improvements for managing multiple hubs and maintaining registrations after import:

- Named private hub profiles with explicit activation, read/admin credential reference separation, and previewed mutations.
- Import-profile selection and source-path editing without discarding managed ownership or automatically pruning registrations.
- A unified status report for registry access, registration counts, local source drift, environment prerequisites, and stored metadata observations.
- Revision-bound metadata freshness and explicit consumer-side inspection/refresh of stale, changed, unknown, or unsuccessful targets.
- Transactional, bounded registry history and guarded single-target undo that refuses subsequent edits and deletion/recreation conflicts.
- Guided first-use setup that composes source selection, previewed registration, optional import-profile storage, and explicitly selected client configuration output.

See [the management guide](../environment-management.md) for commands, limits, credential precedence, partial failures, and recovery.

## Compatibility and scope

Node.js 24+ remains required. SQLite schema advances from 2 to 3 transactionally and accepts existing versions 0–2. Preserve a database backup before upgrading; older binaries reject schema 3. Existing target definitions, revisions, snapshot format 1, and MCP/A2A discovery messages remain compatible. New HTTP APIs provide administrator history/undo and observation recording, with read-only metadata freshness. Discovery is still separate from execution.

Hub profiles are local, private, and independent of import profiles and server setup. Their active selection never changes `serve` or `init`. Credential values remain in the consuming environment. Metadata observations explicitly identify consumer reports and never assert tool/task execution. Existing metadata commands do not implicitly record observations.

History starts at upgrade time and retains at most 1000 events within a 16 MiB UTF-8 definition/overhead budget. It is not an archival audit system. Undo restores registry definitions only and does not rewrite import ownership or reverse external effects. Inspect full history definitions only through administrator access.

## Verification and publication

Release requires regression/type checks, installed-package verification of all six workflows, native Linux/macOS/Windows checks, and container checks. Exact release assets must be verified before publication. Local execution, CI execution, GitHub release availability, and public npm availability are separate gates; no configured-but-unrun check implies a passed result.
