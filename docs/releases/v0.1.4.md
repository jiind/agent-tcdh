# AgentTCDH v0.1.4

Version `0.1.4` adds preview-first batch metadata refresh, explicit target groups for diagnosis and refresh, and local CLI version/runtime identity. Consumers still discover connection metadata centrally and execute directly against their selected targets.

Release preparation is separate from publication. Source metadata and candidate verification do not establish that npm or GitHub publication has completed. Confirm the requested destination before installing from it.

## Included changes

- `target refresh --all`: collect a bounded, filtered group and preview remote metadata changes. Explicit `--apply` saves changed registrations independently with per-target version checks. Unchanged definitions retain their versions and timestamps.
- `doctor --select ID --select ID` and `target refresh --select ID --select ID`: resolve an explicit group without enumerating catalog pages, preserve request order, and validate every selected registration before provider work. Missing/unreadable IDs or disabled entries without `--include-disabled` reject the complete selection.
- `--version` / `-v`: print the declared package version without loading configuration, resolving credentials, or contacting a hub. `--version --json` includes the CLI name, version, Node version, platform, and architecture. Doctor reports include the same local runtime identity.

See [batch metadata refresh](../batch-refresh.md), [explicit target selection](../target-selection.md), and [runtime diagnostics](../onboarding.md#local-version-and-runtime) for options, limits, and outcomes.

## Install a prepared candidate

Requires Node.js 24 or newer. From the verified release source checkout, prepare and verify a new local bundle as described in the [release process](../releasing.md). For output directory `release/v0.1.4`:

```sh
npm install --global ./release/v0.1.4/agent-tcdh-0.1.4.tgz
agent-tcdh --version --json
```

The bundle contains the built CLI tarball, `release.json`, and `SHA256SUMS`, bound to the exact source commit. Preparation does not create a tag, publish a GitHub release, or publish to npm.

## Published artifacts

Check npm availability before using the new version:

```sh
npm view agent-tcdh@0.1.4 version
```

After npm reports `0.1.4`, install with `npm install --global agent-tcdh@0.1.4` or run `npx --yes agent-tcdh@0.1.4 --version --json`. Existing hub configuration and registry storage can be reused.

Confirm that the GitHub `v0.1.4` release exists before downloading its built tarball, manifest, and checksums. Verify the exact release bundle from the tagged source checkout. GitHub and npm publication are separate; publish the same verified tarball and verify its public registry integrity and `latest` tag afterwards. A configured workflow does not establish package-side npm trusted-publisher authorization.

## Compatibility and verification scope

The minimum Node.js version remains 24, SQLite schema remains version 2, and portable snapshots remain format version 1. HTTP/MCP/A2A contracts and existing registrations are unchanged. No dependency changes or database migration are needed. Doctor JSON adds a top-level `runtime` object; existing status and exit semantics are preserved.

Batch refresh performs outbound metadata inspection in the CLI environment, including in preview mode. It does not execute tools/tasks or launch registered stdio commands. Unsupported transports/authentication are skipped; supported Bearer credentials come from each target's own environment reference. Hub credentials are not reused for providers. Selection defaults to at most 100 targets (maximum 1000), with concurrency 3 (maximum 8).

Selection and inspection are observations, not a transactional snapshot. Apply performs fresh lookups/inspection and is not bound to an earlier preview. Conditional writes are independent: failures do not roll back successful updates, and conflicts are not automatically retried. Review individual outcomes before retrying. Explicit groups validate completely before provider work, but registrations can still change later.

Version/runtime identity describes the local CLI process, not the remote hub or consuming agent. The declared version does not identify a Git revision or certify which unreleased changes a source checkout contains.

Local and native CI use isolated configuration files and local protocol fixtures. The matrix covers Linux x64, macOS ARM64/x64, Windows x64, and an independent Linux container. Package verification exercises explicit HTTP/stdio MCP diagnosis groups, remote MCP batch refresh and no-op preservation, configuration-independent installed version output, discovery protocols, persistence, and direct-call examples. The exact release bundle is separately verified before publication.

Earlier live provider and model evidence retains its original dates and scope. This release does not establish new model-driven executions for each supported client. External calls and real model runs remain opt-in. Consumers own target selection, credentials, protocol support, permissions, and execution.
