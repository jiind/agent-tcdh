# AgentTCDH v0.1.7

This release improves first-use discovery, search quality, and day-to-day CLI management.

- Compare compact results across HTTP, MCP, and A2A. Search names, capabilities, tags, and aliases. Optional diagnostics show why terms matched, which filters excluded candidates, and suggestions missing one term.
- Filter by registered transport, authentication type, and stored observation freshness. Inspect required input names and declared types in capability summaries.
- Fetch up to ten selected definitions in one ordered lookup. The CLI adds terminal checkboxes, private reusable searches, and Bash, Zsh, and PowerShell completion.
- Page through results with a cursor that detects registry writes. SQLite ranks against compact searchable metadata and reads full definitions for the returned page. In a 4,000-target benchmark, first-page keyword-search p95 fell from 468 ms to 56 ms with identical ranked IDs and totals.
- Preview client settings with a redacted change plan, get recovery commands from `status`, and stream synchronization previews when pinned source files change.
- Verify Codex and OpenCode 1.x and 2.x configuration layouts against a local MCP fixture. An opt-in real-agent harness audits filtered summary discovery and exact batch selection.

See the [CLI and protocol reference](../reference.md), [environment management guide](../environment-management.md), and [search verification](../search-verification.md).

## Compatibility

Node.js 24 or later is required. The hub adds derived search metadata on first open inside a SQLite transaction and retains schema version 3. Snapshot format 1 continues to accept existing definitions. New aliases are optional. Back up the database before upgrading. Existing search calls retain full results and offset pagination by default.

Search and management previews use registered metadata. The consumer retains target credentials, protocol execution, and permissions. Stored observations report metadata inspection.

## Verification

The release workflow checks native Linux, macOS Apple Silicon and Intel, Windows, and a Linux container, then verifies the exact package before uploading it. The npm publishing workflow installs and verifies the GitHub release tarball before publishing it with npm trusted publishing. External providers and real-model runs are separate opt-in checks.
